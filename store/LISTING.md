Copy these into the Chrome Web Store Developer Dashboard. The images are in this folder and are regenerated by `npm run store-assets`.

## Store listing tab

**Name:** Paper Q&A

**Summary** (132 characters max):

> Ask Claude questions about a research paper PDF and see every answer backed by verbatim quotes highlighted in the PDF.

**Description:**

```text
Paper Q&A turns any PDF into something you can question. Open a research paper, type your questions, and get short answers from Claude. Every answer is backed by quotes copied word for word from the paper and highlighted in place.

HOW IT WORKS
• Open a PDF in Chrome. Paper Q&A offers to open it in its own viewer, built on Mozilla's pdf.js.
• Type one or more questions in the sidebar and press "Find answers".
• Each question gets a color. Its supporting quotes are highlighted in the PDF, and clicking a quote jumps straight to it.
• If the paper doesn't answer a question, Paper Q&A says so instead of guessing.

BUILT FOR REAL PAPERS
• Quotes are located even across two-column layouts, hyphenated line breaks, ligatures, page breaks and dropped citation numbers.
• Approximate and low-confidence matches are clearly labeled.
• Export a copy of the PDF with the highlights saved as real PDF annotations, visible in Acrobat, Preview and any other reader.

• Select a passage and ask about it directly: "what does this mean?" or "how is this computed?" is answered about that passage, with the rest of the paper as context.

• Need something other than a short answer? Ask for a free-form answer, such as a table of every dataset or the hyperparameters as JSON, and Claude follows your format, quoting the paper only where it helps.

• Optionally let Claude search the web for a question. Those answers list the pages they rely on, with links and supporting quotes.

• Export the questions, answers and quotes, with page numbers, as a Markdown file for your notes.
• Answers are cached per file, so reopening a paper brings its highlights back instantly at no extra cost.

READ PAPERS FASTER
• Click a citation to preview the cited paper: title, authors, venue, citation count, a short summary and the abstract, with links to Google Scholar, arXiv and the PDF. Open the cited paper in Paper Q&A with one click.
• The paper info button shows the same for the paper you're reading, with its BibTeX.
• Make Paper Q&A your default PDF viewer: PDFs open in it straight away, and the address bar still shows the PDF's own URL. Switching back to Chrome's viewer takes one click.
• Works with local files too (enable "Allow access to file URLs").

YOUR KEY, YOUR DATA
• Bring your own Anthropic API key. It is stored only in your browser.
• The extension has no server and no analytics. The paper's text and your questions go only to Anthropic's API, and only when you press "Find answers". Pointing at or clicking a citation, or clicking the paper info button, looks up just that paper's reference, title or ID in public scholarly databases (Semantic Scholar, Crossref, OpenAlex, arXiv).
• Choose the model (Claude Opus, Sonnet, Haiku or Fable) and how much effort it spends.

LIMITATIONS
• Scanned PDFs without selectable text can't be read. Run them through OCR first.

Paper Q&A is open source (MIT): https://github.com/mohph197/pdf-qna
Paper Q&A is an independent project and is not affiliated with or endorsed by Anthropic. "Claude" is a trademark of Anthropic.
```

## Privacy practices tab

**Single purpose:**

> Answer the user's questions about a PDF document with Claude and highlight the supporting passages in the PDF.

**Permission justifications:**

| Permission | Justification |
| --- | --- |
| `storage` | Saves the user's API key, settings, and the questions and answers for each PDF so highlights return when the PDF is reopened. |
| `unlimitedStorage` | The per-PDF answer cache can grow beyond the default quota for users with many papers. |
| `tabs` | Reads the URL of the current tab to recognize PDFs (including `file://` PDFs), to open them in the extension's viewer (immediately, if the user made it the default PDF viewer), and to reload the viewer at its readable address. |
| `scripting` | Injects a small "Open in Paper Q&A" banner into a tab that is showing a PDF. Nothing else is injected, and only into PDF tabs. |
| `webRequest` | Observes (does not block or modify) the `Content-Type` of top-level page loads to recognize PDFs whose URL doesn't end in ".pdf", such as arxiv.org/pdf/… links, and, when the user made Paper Q&A the default PDF viewer, to open them in it right away. |
| `notifications` | Fallback offer to open a PDF when a banner can't be shown in the tab. |
| `contextMenus` | Adds an "Open PDF in Paper Q&A" item for links. |
| Host permission `<all_urls>` | Needed to download the PDF the user chooses to open, from whatever site it is on (with the user's cookies, for papers behind a login), to detect PDF tabs on any site, and to call `api.anthropic.com` and, when the user points at or clicks a citation or clicks the paper info button, the public scholarly APIs `api.semanticscholar.org`, `api.crossref.org`, `api.openalex.org` and `export.arxiv.org`. The extension reads no other page content. |

**Remote code:** No, I am not using remote code. All JavaScript, including pdf.js and pdf-lib, is bundled in the package. Scripts embedded in PDFs are never run.

**Data usage.** Tick these:

- **Website content.** The text of the PDF the user opens is sent to Anthropic's API when the user asks a question. When the user points at or clicks a citation, or clicks the paper info button, that paper's bibliography entry, title or identifier is sent to public scholarly APIs (Semantic Scholar, Crossref, OpenAlex, arXiv) to look it up.
- **Authentication information.** The user's own Anthropic API key is stored locally and sent only to Anthropic's API. An optional Semantic Scholar API key is stored locally and sent only to the Semantic Scholar API.

Then certify all three statements:

- I do not sell or transfer user data to third parties, outside of the approved use cases.
- I do not use or transfer user data for purposes that are unrelated to my item's single purpose.
- I do not use or transfer user data to determine creditworthiness or for lending purposes.
